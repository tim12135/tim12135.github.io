Lock、ReentrantLock

锁的颗粒度想要细化到指定字符串

方法 1：使用 ConcurrentHashMap

  • 只有相同 key 才会竞争，不同 key 并行
  • 锁对象是 new Object()，与字符串常量池无关，不会误伤其他代码
  • ConcurrentHashMap 保证 computeIfAbsent 原子性，不会创建出两个锁对象

方法 2：使用 Striped 锁

  • 内部维护一个固定大小的 Lock[]，key 先哈希再取模，不同 key 可能映射到同一把锁
  • 适合海量 key 但又能接受少量哈希冲突的场景，节省内存

方法 3：直接 synchronized(string.intern()) —— 不推荐

  • intern() 会把字符串加入全局常量池，生命周期几乎与 JVM 相等，极易造成隐式全局锁
  • 还会污染常量池，性能、可维护性、安全性都差，生产代码不要使用
