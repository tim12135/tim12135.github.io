FTP操作卡住问题记录

问题现象

2026-07-09 03:39:37，生产环境中 FtpsFileResourceServiceImpl#downloadFiles 方法在调用 ftpClient.listFiles() 后无限阻塞，不再往下执行，日志停在了：

之后再无任何 FTP 日志输出，方法一直卡住。

完整日志

原因分析

直接原因：FTP 使用了主动模式（PORT），数据通道建立失败

日志中出现了 PORT 10,221,8,11,158,135 命令，这是主动模式的标志。其含义是：

  • 客户端告诉 FTP 服务器：”请向 10.221.8.11:40583（158×256+135）发起 TCP 连接来建立数据通道”
  • 服务器回复 200 PORT command successful，随后发送 150 Opening ASCII mode data connection
  • 但服务器实际回连客户端内网地址 10.221.8.11 时，由于 NAT/防火墙的原因，该地址对服务器不可达
  • 数据通道始终无法建立，listFiles() 无限等待

根本原因：代码默认未启用被动模式，也未设置任何超时

  1. FtpsWrapper.configureClient() 从未调用 enterLocalPassiveMode()，Apache Commons Net 默认使用主动模式。

  2. FtpsFileResourceServiceImpl.downloadFiles() 中有被动模式开关：

    但 FileResourceConfig.ftpLocalPassiveMode 的数据库默认值为 false，被动模式未被启用。

  3. 未设置任何超时——实际连接使用的 FTPClient 没有设置 setConnectTimeout、setDefaultTimeout、setDataTimeout，数据通道连不上时无限阻塞，不会报错也不会超时。

主动模式 vs 被动模式

主动模式（PORT） 被动模式（PASV）
数据通道建立 服务器主动连接客户端 客户端主动连接服务器
日志特征 PORT 命令 PASV 命令
NAT/防火墙 需服务器能回连客户端内网，通常失败 客户端主动出连，通常可通
适用场景 客户端有公网IP 现代网络环境（推荐默认）

解决方案

在 FtpsWrapper.configureClient() 中统一设置被动模式和超时：

各超时说明

方法 作用 说明
setConnectTimeout(30000) 连接 FTP 服务器超时 30秒内连不上则报错
setDefaultTimeout(60000) 控制通道（命令）读取超时 60秒内收不到服务器响应则报错
setDataTimeout(60000) 数据通道（LIST/RETR等）读取超时 60秒内数据通道无数据读取则报错，防止无限挂起

注意：setDataTimeout 设置的是 socket 的 SO_TIMEOUT，即两次数据读取之间的最大间隔，不是总传输时间限制。大文件下载只要数据持续流式传输就不会被中断，只有网络卡死或断开时才会触发超时。
